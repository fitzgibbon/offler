#+title: offler — a unified graphics, windowing and audio library for Idris 2
#+options: toc:2

One Idris API over three graphics targets: WebGL2 and WebGPU in the browser
(=idris2 --cg javascript=), and SDL3 + wgpu-native on the desktop
(=idris2 --cg chez=). Applications are written against four interfaces —
=Renderer=, =Platform=, =Audio= and =Material= — and never name a graphics
API, a window system or a sound server. =Platform= carries the full input
vocabulary: keyboard, pointer (absolute, relative and locked), touch as
first-class events, and polled gamepads; =Audio= is Web Audio in the
browser and an SDL3 mixer natively, with retained sounds and generational
voice handles. A whole program is an =App= — a title and one polymorphic
scene function — and a backend *launcher* (=Offler.Native.App=,
=Offler.Web.App=) constructs the renderer, platform and audio around it,
so each entry point is a single =launch app= line.

The model is *retained*, as bevy's is: meshes, textures and material assets
are created once and referenced by typed handles; objects live in a scene
graph of transforms; a frame moves some nodes and renders the scene. Where
bevy derives its GPU-facing machinery with proc macros and checks its
invariants at runtime (pipeline specialisation, bind-group layouts), offler
derives them in the type checker: generated-and-proved layouts, phantom-
typed handles, and compile-time bounds where bevy has panics.

The architecture is the one proved out by the orrery example in
=~/src/idris-sandbox/examples/orrery=, whose =ENGINE-NOTES.md= is the design
rationale this library executes: everything measured or hit as a real error
there is either adopted or guarded against here. The API surface follows the
graphical parts of [[https://bevyengine.org][bevy]] — =Transform=, =StandardMaterial=, =Camera= +
=Projection=, mesh primitives, lights — reduced to what one forward pass
honours.

* Quick start

#+begin_src sh
  nix develop        # Idris 2, Chez, SDL3, wgpu-native, and the headless test rig
  make               # every example: two browser bundles and a native binary each
  make web           # just the bundles; then open shapes.html — no server needed
  make run-shapes    # build and launch a native example
  make check         # the programs that must fail to compile
  make lib           # build the library alone (offler.ipkg)
#+end_src

* The examples

Each example is one backend-agnostic =Scene.idr= exporting an =app : App=,
plus three one-line entry points — =MainGl2=, =MainGpu=, =Main= (native) —
each just =launch app= against its backend's launcher, compiled separately
so every build is monomorphic and no bundle carries another backend's code.
The browser pages (=shapes.html= etc.) pick a bundle by URL; the footer
button switches by navigating with =?r=webgpu=.

|------------+---------------+--------------------------------------------------------------------------|

| =Custom=   | =custom.html= | a user-defined material, end to end: a scanline hologram implementing the =Material= interface with its own WGSL and GLSL, =Blend=-composited through =Mask= cutout panels, all as scene-graph nodes over assets |

(=scripts/headless-shot.sh=), and in the browser on *both* backends: WebGL2
at 58 fps on hardware GL (the swarm at 50 000 bodies in one instanced

presenting only a white canvas — browser WebGPU visually confirmed in
headless Chrome 151 under SwiftShader, screenshots and all, driven over CDP

* The abstraction

#+begin_src idris
  interface Renderer r f | r where
    rendererName      : r -> String
    createMesh        : {t : Topology} -> r -> Verts t -> IO (MeshHandle t)
    createMeshIndexed : r -> Verts Triangles -> Indices -> IO (MeshHandle Triangles)
    freeMesh          : r -> MeshHandle t -> IO ()   -- index recycled; stale handles draw nothing
    loadTexture       : r -> TextureSource -> IO TextureHandle    -- immediate; white until decoded
    registerMaterial  : Material m => r -> ...proofs... -> IO (MaterialId m)
    addMaterial       : Material m => r -> MaterialId m -> m -> IO (Handle m)
    updateMaterial    : Material m => r -> Handle m -> m -> IO (Handle m)
    setGizmos         : r -> Verts Lines -> IO ()   -- gizmo plumbing; use Offler.Gizmos
    aspect            : r -> IO Double
    beginFrame        : r -> Camera -> Lights -> (time : Double) -> L1 IO (LMaybe f)
    draw              : Material m => r -> (1 frame : f) -> MeshHandle t -> Handle m -> Mat4
                     -> {auto 0 ok : TopoOk t m} -> L1 IO f
    drawMany          : Material m => r -> (1 frame : f) -> MeshHandle t -> Handle m -> List Mat4
                     -> {auto 0 ok : TopoOk t m} -> L1 IO f
    createInstances   : r -> IO InstanceHandle       -- a GPU instance buffer, grown on write
    writeInstances    : r -> InstanceHandle -> InstSlice -> IO ()
    drawInstanced     : Material m => r -> (1 frame : f) -> MeshHandle Triangles -> Handle m
                     -> InstanceHandle -> Mat4 -> {auto 0 inst : InstOk m} -> L1 IO f
    drawGizmos        : r -> (1 frame : f) -> L1 IO f
    endFrame          : r -> (1 frame : f) -> L IO ()

  interface Platform p where
    runLoop          : p -> (Double -> IO ()) -> IO ()
    pollEvents       : p -> IO (List Event)      -- keys, pointer, deltas, touch, wheel
    gamepads         : p -> IO (List Gamepad)    -- polled: the only model both worlds share
    setPointerLock   : p -> Bool -> IO ()        -- a request; PointerLockChanged is the truth
    setCursorVisible : p -> Bool -> IO ()
    surfaceSize      : p -> IO (Double, Double)  -- the space pointer events report in

  interface Audio a where
    loadSound     : a -> SoundSource -> IO SoundHandle   -- retained; URL decode is async
    play          : a -> SoundHandle -> Playback -> IO Voice
    setVoice      : a -> Voice -> (gain : Double) -> (pan : Double) -> IO ()
    stopVoice     : a -> Voice -> IO ()                  -- stale voices no-op, freeMesh-style
    setMasterGain : a -> Double -> IO ()

  record App where                    -- a whole program, minus its backends
    constructor MkApp
    title : String
    scene : {0 r, f, p, au : Type} -> Renderer r f => Platform p => Audio au =>
            r -> p -> au -> Status -> IO ()
#+end_src

The rank-2 =scene= field is the lifetime guarantee: an =App= receives its
capabilities and cannot conjure others, so the same value launches on all
three targets. Each backend supplies one launcher (=Offler.Native.App.launch=,
=Offler.Web.App.launchGl2= / =launchGpu=) that owns everything outside the
scene — window or canvas, device acquisition (asynchronous on WebGPU),
audio, page chrome — which is why every example's three entry-point
modules are one import and one line.

Decisions carried over from the orrery, with the reasoning:

- No member may name a concept absent on any target. The orrery once had
  =canvasOf : r -> JSVal=; deleting it is what made a native build possible.
  Nothing here mentions a canvas, a window handle, or the DOM.
- The abstraction is WebGPU-flavoured and WebGL2 does extra work to fit, not
  the reverse. GL can emulate pipelines and recorded passes; WebGPU cannot
  emulate GL's mutability. Browser WebGPU and =webgpu.h= are the same API, so
  the C shim is a near-mechanical transliteration of the JS lambdas and two
  of the three backends cost about one and a half.
- Backends are chosen at compile time. Each browser bundle is a separate
  =idris2= invocation against its own =Main=, so the draw loop is
  monomorphic and neither bundle ships the other's code.
- =beginFrame= is fallible in the type. The surface texture can be
  unavailable during a resize; failure means no token, and a draw without a
  token is a compile error, not a flag someone forgot to test.
- The platform owns the loop (rAF in the browser, a =while= natively), and
  input is drained once per frame on the frame thread — browser listeners
  queue into a ref rather than mutating the scene from a callback.

** What offler adds over the orrery

- *Multiple meshes.* =createMesh= returns an opaque =MeshHandle= into a
  per-backend mesh table (a JS array, a realloc'd C array), so a scene draws
  any number of different meshes per frame. The orrery had exactly one.
- *A real material.* Base colour with alpha, emissive, metallic, roughness,
  unlit — encoded into one 112-byte uniform block rather than the orrery's
  tint-plus-mode.
- *Cameras and lights as data.* =Projection= is described, not a baked
  matrix: the renderer builds it against the live aspect at =beginFrame=, so
  resizes never leave a stale projection. The clear colour rides on the
  camera, as in bevy.
- *Transforms.* =Transform= (translation, =Quat= rotation, scale) with
  =matOf=, =viewOf= and =lookingAt=, replacing hand-rolled matrix chains.
- *A general input vocabulary.* Keys (browser =KeyboardEvent.key= spelling,
  which the SDL side translates to match), pointer — absolute, relative
  deltas, and locked — wheel, touch with finger ids (never masquerading as
  mouse events: both backends filter their platform's synthesised
  compatibility clicks), gamepad connect/disconnect plus polled state,
  resize, close. The orrery's =Event= was four application-specific
  constructors, flagged in its notes as the weak point.
- *Sound.* The orrery had none; offler's =Audio= interface is the same
  bargain as =Renderer= — retained sounds, generational voices, one
  vocabulary — over Web Audio and an SDL3 mixer.
- *Two shader entry points.* Lines carry only a position, so =vs_line=
  consumes them directly; no fake normal attribute, and the line pipeline's
  vertex layout is generated from its own field list.

* Materials, textures and alpha: the bevy correspondence

The material system is deliberately a transliteration of bevy's, mechanism
by mechanism:

| bevy                                  | offler                                          |
|---------------------------------------+-------------------------------------------------|
| =trait Material: AsBindGroup=         | =interface Material m= (=Offler.Gfx.Material=)  |
| =#[derive(AsBindGroup)]= uniforms     | =matFields= (generates struct, bindings, offsets) + =writeMat= |
| =#[texture(n)] #[sampler(n)]=         | =matTextureSlots= + =matTextures=               |
| =fragment_shader()= / =vertex_shader()= | =matWgsl=, =matGlslVert=, =matGlslFrag=       |
| =alpha_mode()=                        | =alphaMode : m -> AlphaMode=                    |
| =MaterialPlugin::<M>= registration    | =registerMaterial : IO (MaterialId m)=          |
| =Handle<Image>= / image assets        | =TextureHandle= via =loadTexture=               |
| =StandardMaterial=                    | =Offler.Material.StandardMaterial=, an ordinary instance |
| =Opaque3d= / =Transparent3d= phases   | opaque records in call order; =Blend= queues and replays depth-sorted at =endFrame= |
| =Handle<M>= material assets           | =Handle m=: data uploaded to its own slot at =addMaterial=, zero material work per draw |
| =Mesh= with =PrimitiveTopology=       | =MeshHandle t= indexed by =Topology=; the vertex layout follows the index |
| pipeline specialisation per mesh key  | pipeline variants per (topology × alpha phase), the variant *chosen by the type checker*; a line mesh with a material lacking =vs_line= is a missing =So=, not a runtime error (=TopoOk=) |
| =Indices= / indexed meshes            | =createMeshIndexed=: shared vertices named by a u32 list |
| =bevy_transform= + =bevy_hierarchy=   | =Offler.Scene=: a retained tree, =Transform= per node, propagation to world matrices |
| automatic batching / GPU instancing   | =drawInstanced=: model matrix + colour at instance rate against one material asset, one call per crowd; the material's =vs_inst= entry is demanded by =InstOk= at compile time where bevy's batcher decides at runtime |
| =bevy_gizmos= (immediate)             | =Offler.Gizmos=: =gLine=/=gArrow=/=gAxes=/=gCircle=/=gSphere=/=gCuboid=/=gGrid= over pure =GizmoData=; =drawGizmoData= + =drawGizmos= render the frame's worth, per-vertex coloured, in one blended call |
| =GizmoAsset= + =Gizmo= (retained, 0.14) | =gizmoAsset=: freeze =GizmoData= into a =Lines= mesh drawn by =GizmoMaterial= (an ordinary =Material= whose =vs_line= keeps the per-vertex colours; the tint is the =Gizmo= config), spawn the =Drawable= as a scene node, move it by transform. =retainGizmos= gives the bare mesh for a custom material's =vs_line= |
| =bevy_input= (keyboard, mouse, touch, gamepad) | the =Platform= half of input: one =Event= stream for keys/pointer/touch (SDL names translated to the browser's spelling, fingers never faked as clicks) and =gamepads= polled into one =Gamepad= record — bevy's =Axis=/=ButtonInput= resources are its ECS spelling of the same snapshot |
| =bevy_picking= (pointers → backends → focus) | =Offler.Picking=, the same three layers: mice and fingers unify into =PointerId=; the backend is =pickRay= (the *analytic* inverse of the camera the renderer draws with, so pixels map to world rays exactly at every aspect — no screen-space approximations) cast against declared bounds, =sceneTargets= reading world matrices from the graph where bevy's raycast reads =Mesh= assets; the focus layer is =pickStep=, a *pure* state machine emitting =PickOver=/=PickOut=/=PickDown=/=PickUp=/=PickClick= where bevy dispatches observer events. GPU id-buffer picking, bevy's optional backend, would need render-to-texture and stays out |
| =bevy_audio= (=AudioPlayer=, =PlaybackSettings=) | the =Audio= interface: =loadSound= retains (URL decode async, handle valid at once — the texture bargain), =play= with =Playback= (gain/pan/rate/=semitones=/loop) mints a generational =Voice= where bevy spawns an entity; =SoundPcm= is the procedural path bevy routes through =AudioSource= assets |
| =bevy_app= (=App=, =runner=) | =Offler.App=: an =App= is a title plus one rank-2 scene function; the backend launchers are bevy's runners, each owning its target's startup (the winit loop, or here: SDL3+wgpu, WebGL2, or WebGPU's async adapter). Bevy's plugin/schedule machinery has no counterpart — offler scenes are plain =IO= driven by =runLoop= |

Where bevy derives the GPU-facing description with a proc macro, offler
derives it in the type checker. A material type supplies its uniform block
as a `Layout` field list; the WGSL struct, the GLSL std140 block (identical
layout for these field types — which is what lets all three backends share
the scratch buffers byte for byte), the bind-group spec and the shader
prologue are generated from it. Registration demands two erased proofs,
discharged by reduction at the call site:

#+begin_src idris
  registerMaterial : Material m => r
                  -> {auto 0 sizeOk : FitsSlot m}    -- block fits its 256-byte slot
                  -> {auto 0 texOk : FitsSlots m}    -- texture count fits the bindings
                  -> IO (MaterialId m)
#+end_src

A five-=mat4= material is rejected at compile time
(=Tests/FatMaterial.idr= holds that in place), and =MaterialId m= is
phantom-typed, so pairing one material type's pipelines with another's
values is a type error rather than a wrong image
(=Tests/WrongMaterialId.idr=).

** Textures

=loadTexture= decodes PNG, JPEG, GIF and BMP on every backend — the
browser's own decoder there, =stb_image= in the C shim — into sRGB textures
(linear in the shader, gamma-encoded once at the end). Sources are a path
or URL, or base64 bytes: the examples embed their images as base64 through
a generated module, because a =file://= page taints image loads into WebGL
and blocks =fetch()= outright, while data: URLs are same-origin — the same
reasoning as the embedded shaders, and it keeps binaries asset-free too.
Every unmapped slot binds a built-in 1×1 white, so an absent map multiplies
by one. Meshes carry UVs now (position, normal, uv — 32-byte stride, all
proved in =Layout=); every primitive computes a sensible parametrisation,
the icosphere with the classic spherical-projection seam bevy's also has.

One trap preserved for posterity in the =Web.Gpu= docstrings: *texture*
usage bits are not *buffer* usage bits — =COPY_DST= is 2 for textures and 8
for buffers, and the wrong constant surfaces as an invalid bind group at
draw time, far from the mistake, only on the browser path (the C shim uses
real enums). The device's =uncapturederror= handler now routes such
validation errors into the page's error box.

** Alpha modes and the transparent phase

=AlphaMode= is =Opaque=, =Mask cutoff= or =Blend=, per material *value*.
The mode rides in the per-draw engine block's lane; =Mask= discards in the
shader through the generated =offlerAlpha= helper (so it keeps depth writes
and stays in the opaque phase, as in bevy), and =Blend= draws are queued —
on every backend — and replayed at =endFrame= sorted back to front by
view-space depth, over the finished opaque scene. WebGL2 takes this
furthest: the whole frame is recorded and replayed at =endFrame= after one
prefix upload of each slot buffer, because per-draw =bufferSubData= was
measured at a quarter of the frame rate at ten thousand bodies.

* The scene graph, and what it does (not) depend on

The question that decided this architecture: does bevy's scene graph need
its ECS, or its renderer? Neither, conceptually. In bevy the hierarchy
(=ChildOf=/=Children=) and the transforms live as components and the
propagation pass is a system -- the ECS is the *host* -- but nothing about
a tree of transforms with a multiply-down pass requires an ECS, and the
render backend never sees the tree at all: it consumes the propagated
=GlobalTransform=s.

=Offler.Scene= is therefore a plain retained tree behind an =IORef=:
=spawn= under a parent, =setTransform= to animate, =despawn= a subtree,
=collect= to propagate and flatten into =(world matrix, Drawable)= pairs,
=renderScene= to draw them. The graph knows nothing about backends; the
backends know nothing about the graph; the whole seam is one list type.
Nodes hold a =Drawable= -- an existential pairing a mesh handle with a
material handle, the topology-compatibility proof captured at construction
and erased -- so a scene mixes material types freely while an
ill-topologied node cannot even be built.

There is no dirty tracking: propagation is a full multiply-down per frame,
which at scene-graph granularity (dozens to hundreds of nodes) is nothing.
Crowds do not belong in a graph -- the Swarm example keeps its fifty
thousand bodies in a flat list and draws them with =drawInstanced=,
which is how bevy renders crowds too (one material asset, one instanced
call).

* Retained materials

A material *asset* (=Handle m=, bevy's =Handle<M>=) owns a 256-byte slot
of the material buffer and, on the WebGPU-flavoured backends, a cached
bind group -- both made at =addMaterial=, when =writeMat= runs and the
block is uploaded. After that, drawing with the handle costs no material
work at all: a draw writes the engine block (model matrix, alpha lane)
and one foreign call. The measurable consequence: a frame's uploads are
one prefix per touched object-buffer page and nothing else.

Alpha phase rides in the handle (an asset is immutable; =updateMaterial=
refills the slot and mints a fresh handle), =Mask= discards in-shader via
the generated =offlerAlpha=, and =Blend= draws queue on every backend and
replay depth-sorted at =endFrame= over the finished opaque scene.

* The linear frame token

=beginFrame= mints a linear token; every draw consumes and re-issues it;
=endFrame= consumes it finally. Drawing after the end, dropping a begun
frame, or drawing twice from one token are type errors, checked by
=make check= against the exact expected diagnostic (=Tests/=). The rule the
orrery measured, kept here: *linear tokens sit at resource boundaries and
are never threaded through a per-item loop.* =runK='s recursion is not a
self tail call, so each bind costs a stack frame on the JS backend and
overflows between 8 000 and 10 000 binds — hence =drawMany=, which loops
inside one lifted =IO= action -- and =Checks/StackCheck.idr= holds the
trampoline property in place directly.

* One description of the GPU contract

=Offler.Gfx.Layout= holds the uniform blocks, their fields, and both vertex
layouts. Everything else is derived:

- the WGSL =struct Globals= / =struct Obj= / =struct VertexIn= /
  =struct LineIn= and their =@group/@binding= declarations, prepended to the
  authored shader;
- the GLSL =layout(location=n) in= declarations, spliced after =#version=;
- the bind-group-layout and vertex-attribute *spec strings* that both
  WebGPU-flavoured backends decode once at startup — Idris cannot build a
  nested descriptor across either FFI, so the description crosses as
  =0,3,0,176;1,3,1,112= and five lines of JS or fifteen of C decode it;
- every byte offset and stride the pokes use, as *literals proved equal to
  the computed layout* at multiplicity 0:

#+begin_src idris
  globalSize : Int
  globalSize = 176

  0 globalSizeOk : Layout.globalSize = Layout.structSize Layout.globalFields
  globalSizeOk = Refl
#+end_src

Grow the object uniform past its slot, misalign a field, or declare a vertex
attribute wider than one location, and the module stops compiling. The
guarantees follow the orrery's cost ladder: erased indices and private
constructors (free) catch most of the real bugs; the one checked-at-runtime
step is =slot=, a single comparison covering both the scratch bound and the
dynamic offset, because =objFloats * 4 = objStride= is proved.

What is deliberately /not/ guaranteed: two arrays of equal capacity remain
interchangeable, and a computed index is tested rather than proved — =Int=
is primitive, so its order theory would have to be postulated (the
=Data.Int.Order= pattern), and multiplication monotonicity is missing there.
Bounds arithmetic is written not to overflow (=i <= n - w=, never
=i + w <= n=), which matters because =Int= is 32-bit on the JS backend.

** The run-time bounds tests, and turning them off

The erased indices, the proofs, the private constructors and the linear
token cost nothing at run time — erasure is free, so there is nothing to
toggle there. The only checks that run are:

- =window= / =slot=, the checked constructors, which §8.1 of the orrery's
  notes priced at +43 ns per object on Chez and +20 ns on Node — and
  attributed to the =Maybe= they allocate, not to the comparison. offler
  keeps them on the /cold/ paths only: single =draw= calls, line overlays,
  mesh uploads.
- The per-object hot path — =drawMany='s batch fill — goes through
  =pokeObjects= instead, whose bound is a bare comparison inside the module
  that owns the invariant. The test still runs *for every object*: what
  moved is its form (a branch instead of an allocated =Maybe=) and its
  justification, not its frequency or its accuracy. =0 <= i < maxObjects=
  is equivalent to the window test =slot= performs, because the scratch is
  allocated as exactly =objFloats * maxObjects= floats; slot bases step by
  exactly =objFloats=, so in-range slots are disjoint; and the writes
  *inside* a slot remain proof-bounded by the erased =sub= offsets. What is
  genuinely weaker: the tie between the test and the construction is now
  module-level reasoning over ten private lines (=slotAt= asserts with
  =unsafeAt=) rather than a type — which is why the loop is private,
  single, and run at exactly the cap by =Checks/StackCheck.idr= on every
  =make check=. Proving the tie instead would need multiplication
  monotonicity for =Int=, which not even contrib's =Data.Int.Order=
  postulates. =slot= remains the only way in from outside, and =make
  check= still proves it (=Tests/ForgedSlot.idr=).

On top of that sits the switch:

#+begin_src sh
  make BOUNDS=trusted      # batch bounds tests off
  make                     # BOUNDS=checked is the default
#+end_src

The flag becomes the generated =Offler.Gfx.Config= module — the same
mechanism as the embedded shaders, regenerated only when the value changes —
whose =boundsMode : Bounds= is a compile-time constant. =pokeObjects=
branches on it /once, outside the loop/, and because the constant reduces,
the untaken loop is dead code: a =trusted= bundle contains no =goChecked=
at all, verifiable by grep. An earlier design indexed the API by a
type-level flag with the result type computed from it
(=Checked ↦ Maybe (At cap w)=, =Trusted ↦ At cap w=); it works, but every
call site must then handle both result types, and the toggle becomes the
complexity. A value-level constant that constant-folds gets the same
machine code without bifurcating the API.

=Trusted= is only sane when the application bounds its own draw count:
past the cap, the JS backend silently drops the writes and the C side
corrupts the heap. The default is =checked=, and since the checked test is
a bare comparison the notes measured as free, there is little reason to
ship =trusted= — it exists to make the cost of the guarantee inspectable
rather than argued about.

* Performance rules inherited as architecture

From the measurements in the orrery's notes, taken as constraints rather
than advice:

- Hot numeric data lives in flat foreign =Float32Array= / =float*= buffers,
  not Idris records; Chez heap-allocates every intermediate flonum and is
  roughly 5× slower than V8 on record-heavy per-frame work.
- Foreign calls are batched around the natural unit of the data: =poke16=
  writes a whole matrix, line vertices are padded to four floats so one call
  writes two of them, and per-object uniforms are filled CPU-side and
  uploaded in *one* =writeBuffer= per frame — per-object queue writes are
  what once made WebGPU a third of WebGL2's speed.
- Nothing per-frame builds lists with non-tail recursion. The Prelude's
  ranges overflow V8 near 5 700 elements (=takeUntil= has no accumulator
  transform), so =Offler.Math.range= is total, tail-recursive, and
  ascending-or-empty.
- Batched draws loop on the far side of the FFI where possible:
  =drawMany= records its slices in one foreign call on both WebGPU-flavoured
  backends.

* The native build

Same scene code, compiled with =--cg chez=. SDL3 rather than GLFW because
wgpu wants a =CAMetalLayer= on macOS and =SDL_Metal_CreateView= produces one
without Objective-C. Surface creation is the only per-platform function,
selected on =SDL_GetCurrentVideoDriver()= at run time (X11 and Wayland in
one binary). The C shim holds no scene logic and no layout constants — the
specs arrive from =Offler.Gfx.Layout= at init. The Makefile drops
=liboffler.so= into each =build/exec/<example>_app/=, where the generated
launcher's =LD_LIBRARY_PATH= already points, so binaries run with no
environment set.

Headless verification:

#+begin_src sh
  nix develop --command scripts/headless-shot.sh shapes /tmp/shapes.png 8
#+end_src

runs an example under Xvfb with lavapipe as the Vulkan device and grabs the
window. The script encodes the two traps: SDL3 prefers Wayland whenever
=WAYLAND_DISPLAY= is set regardless of =DISPLAY=, and wgpu dlopens
=libvulkan.so.1=, which the dev shell puts on the library path.

* Known limits, in the order they would matter

- Textures are base-colour only: no mipmaps (linear filtering), no normal /
  metallic-roughness / emissive maps — more slots are one =matTextureSlots=
  entry each, but the standard shader only samples one. At most 4 texture
  slots per material (the C FFI's fixed arity, proved at registration).
- A =drawMany= batch is one material asset and many matrices; per-item
  colour wants =drawInstanced=, whose instance stream carries a colour
  beside each matrix.
- Transparent draws sort by object centre, the classic approximation;
  intersecting geometry can still composite wrongly, as in bevy.
- Directional lights only (four), no point/spot, no shadows.
- Instanced draws run in the opaque phase: a batch cannot be depth-sorted
  within itself (bevy's batches have the same limitation), so =Blend=
  materials want per-node draws.
- There is no per-frame draw ceiling: the object and material buffers are
  *paged*, =maxObjects= (10 240) slots of 256 bytes per page, pages made
  the first time a slot on them is used. =drawMany= chunks batches at page
  boundaries; =endFrame= uploads one prefix per touched page. The
  instance path bypasses object slots entirely -- a 50 000-body crowd
  spends one.
- Meshes can be released with =freeMesh=: the GPU buffers go, the index
  returns to a free list, and the entry's *generation* bumps -- handles
  carry the generation they were minted at, so a stale handle (even one
  whose index has been recycled) draws nothing rather than someone else's
  mesh. Nothing leaks and nothing dangles; the check is one integer
  compare per draw. Unrestricted handles cannot make use-after-free a
  type error the way the linear frame token can -- bevy frees on refcount
  for the same reason. Textures and material assets are still permanent:
  their views live inside cached bind groups, so freeing them needs the
  =texGen= rebuild machinery extended, not just a delete.
- Sound before the first user gesture is silently dropped in the browser:
  the autoplay policy suspends the =AudioContext= until a real key, click
  or touch, and the web backend resumes itself on the first one. Scenes
  that play on input never notice; a title-screen jingle would.
- =SoundFile= decodes whatever the browser's =<audio>= decodes on the web,
  but only WAV natively (SDL3 ships no other decoder). =SoundPcm= — mono
  samples synthesised in Idris — is byte-identical everywhere and needs no
  files, which is what the chime uses.
- The native mixer is a fixed pool of 64 voices; a 65th simultaneous play
  returns =noVoice= (the browser allocates nodes and has no such ceiling).
  Stopped and finished voices recycle through generations, so a stale
  =Voice= controls nothing — the =freeMesh= scheme.
- =setPointerLock= is a *request*. The truth arrives as a
  =PointerLockChanged= event: browsers grant only shortly after a real
  user gesture, may decline silently (no event), and exit on =Escape= by
  themselves; SDL grants synchronously and the event arrives on the next
  poll. Scenes that mirror their own requests instead of tracking the
  event drift out of sync -- the chime tracked its toggle key at first,
  and a declined grant left it steering by deltas it never got.
- =Escape= closing the native window is platform policy, not scene code.

* Testing

- =make check= — ten programs that must fail to compile, each asserting
  /why/ it was rejected (a linearity error, a private constructor, a =So=
  bound, a stride mismatch, an oversized material block, a =MaterialId=
  paired with the wrong material type, a line mesh drawn with a material
  that has no line entry points, an instanced draw against a material
  with no instanced entry). A negative test that does not say
  why is not a test: the orrery's first version passed vacuously on
  misnamed modules.
- =Checks/StackCheck.idr=, run by =make check= — the other kind of
  guarantee: a program that must /run/, filling all 10 240 slots on the
  node backend, where the stack is scarcest, plus a grep of the generated
  output for the =__tailRec= trampoline the loop depends on. It exists
  because the first version of =pokeObjects= compiled to a curried
  recursion the trampoline could not see and overflowed V8 at exactly the
  cap — invisible in the source, invisible to every compile-time check,
  caught only by running the loop at scale and reading the output. (The
  fix: the loop is written in =PrimIO= with the world bound on the
  left-hand side, so the recursive call is saturated and trampolines.)
- =scripts/headless-shot.sh= — pixels from the native build without a GPU or
  a display.
- The browser pages surface uncaught errors and unhandled rejections into a
  visible error box, because most of the startup path is asynchronous and
  would otherwise fail to a silent blank canvas.
