#+title: offler — a unified graphics and windowing library for Idris 2
#+options: toc:2

One Idris API over three graphics targets: WebGL2 and WebGPU in the browser
(=idris2 --cg javascript=), and SDL3 + wgpu-native on the desktop
(=idris2 --cg chez=). Applications are written against two interfaces —
=Renderer= and =Platform= — and never name a graphics API or a window system.

The architecture is the one proved out by the orrery example in
=~/src/idris-sandbox/examples/orrery=, whose =ENGINE-NOTES.md= is the design
rationale this library executes: everything measured or hit as a real error
there is either adopted or guarded against here. The API surface follows the
graphical parts of [[https://bevyengine.org][bevy]] — =Transform=, =StandardMaterial=, =Camera= +
=Projection=, mesh primitives, lights — reduced to what one forward pass
honours.

* Quick start

#+begin_src sh
  nix develop        # Idris 2, Chez, SDL3, wgpu-native, and the headless test rig
  make               # every example: two browser bundles and a native binary each
  make web           # just the bundles; then open shapes.html — no server needed
  make run-shapes    # build and launch a native example
  make check         # the programs that must fail to compile
  make lib           # build the library alone (offler.ipkg)
#+end_src

* The examples

Each example is one backend-agnostic =Scene.idr= plus three entry points —
=MainGl2=, =MainGpu=, =Main= (native) — compiled separately so every build is
monomorphic and no bundle carries another backend's code. The browser pages
(=shapes.html= etc.) pick a bundle by URL; the footer button switches by
navigating with =?r=webgpu=.

| example    | page          | demonstrates                                                             |
|------------+---------------+--------------------------------------------------------------------------|
| =Shapes=   | =shapes.html= | bevy's =3d_shapes=: five rotating primitives over a ground plane, one directional light, the metallic and roughness ranges |
| =Lines=    | =lines.html=  | line-list rendering: a wireframe globe, an animated Lissajous ribbon with glowing markers, a grid — one blended draw, rebuilt on the CPU every frame |
| =Swarm=    | =swarm.html=  | batched drawing at scale: up to 10 000 lit bodies around an emissive core in a single =drawMany=; =+=/=-= double and halve the count |
| =Flat2d=   | =flat2d.html= | the 2D mode: an orthographic camera and unlit materials over the same 3D pipeline |

All four are verified rendering natively under Xvfb + lavapipe
(=scripts/headless-shot.sh=), and in the browser on WebGL2 at 58 fps — the
swarm at the full 10 000 with no stack growth. Browser WebGPU initialises and
records identically to the native wgpu path (same descriptors, same
generated layout) but, as with the orrery, headless Chrome cannot present it,
so visual confirmation of that one path needs a real browser on real
hardware.

* Layout of the library

Three layers: what every target shares, what the browser adds, what the
desktop adds.

| module                  |                                                                     |
|-------------------------+---------------------------------------------------------------------|
| =Offler.Math=           | =V3=, =Quat=, =Mat4=; perspective, orthographic, =lookAt=; the clip-space correction; a total, tail-recursive =range= |
| =Offler.Color=          | linear-RGB colours; =srgb= / =hsl= author in familiar terms and convert |
| =Offler.Transform=      | translation–rotation–scale, composed in bevy's order; =viewOf= as the rigid inverse |
| =Offler.Camera=         | =Projection= (perspective or orthographic) + pose + clear colour; the matrix is built by the renderer against the live aspect ratio |

| =Offler.Mesh=           | primitives with normals: cuboid, icosphere, plane, torus, cylinder, cone, circle, rectangle; line builders |
| =Offler.Gfx.Array=      | =F32Array= indexed by capacity, =At= positions, =Verts= indexed by stride; the =Bounds= mode |

| =Offler.Gfx.Uniform=    | the two uniform scratches and the only writers into them            |

* The abstraction

#+begin_src idris
  interface Renderer r f | r where
    rendererName : r -> String
    createMesh   : r -> Verts Layout.meshFloats -> IO MeshHandle
    setLines     : r -> Verts Layout.lineFloats -> IO ()
    aspect       : r -> IO Double
    resize       : r -> IO ()
    beginFrame   : r -> Camera -> Lights -> (time : Double) -> L1 IO (LMaybe f)
    draw         : r -> (1 frame : f) -> MeshHandle -> Mat4 -> Material -> L1 IO f
    drawMany     : r -> (1 frame : f) -> MeshHandle -> List (Mat4, Material) -> L1 IO f
    drawLines    : r -> (1 frame : f) -> Material -> L1 IO f
    endFrame     : r -> (1 frame : f) -> L IO ()

  interface Platform p where
    runLoop    : p -> (Double -> IO ()) -> IO ()
    pollEvents : p -> IO (List Event)
    setStatus  : p -> (slot : String) -> String -> IO ()
#+end_src

Decisions carried over from the orrery, with the reasoning:

- No member may name a concept absent on any target. The orrery once had
  =canvasOf : r -> JSVal=; deleting it is what made a native build possible.
  Nothing here mentions a canvas, a window handle, or the DOM.
- The abstraction is WebGPU-flavoured and WebGL2 does extra work to fit, not
  the reverse. GL can emulate pipelines and recorded passes; WebGPU cannot
  emulate GL's mutability. Browser WebGPU and =webgpu.h= are the same API, so
  the C shim is a near-mechanical transliteration of the JS lambdas and two
  of the three backends cost about one and a half.
- Backends are chosen at compile time. Each browser bundle is a separate
  =idris2= invocation against its own =Main=, so the draw loop is
  monomorphic and neither bundle ships the other's code.
- =beginFrame= is fallible in the type. The surface texture can be
  unavailable during a resize; failure means no token, and a draw without a
  token is a compile error, not a flag someone forgot to test.
- The platform owns the loop (rAF in the browser, a =while= natively), and
  input is drained once per frame on the frame thread — browser listeners
  queue into a ref rather than mutating the scene from a callback.

** What offler adds over the orrery

- *Multiple meshes.* =createMesh= returns an opaque =MeshHandle= into a
  per-backend mesh table (a JS array, a realloc'd C array), so a scene draws
  any number of different meshes per frame. The orrery had exactly one.
- *A real material.* Base colour with alpha, emissive, metallic, roughness,
  unlit — encoded into one 112-byte uniform block rather than the orrery's
  tint-plus-mode.
- *Cameras and lights as data.* =Projection= is described, not a baked
  matrix: the renderer builds it against the live aspect at =beginFrame=, so
  resizes never leave a stale projection. The clear colour rides on the
  camera, as in bevy.
- *Transforms.* =Transform= (translation, =Quat= rotation, scale) with
  =matOf=, =viewOf= and =lookingAt=, replacing hand-rolled matrix chains.
- *A general input vocabulary.* Keys (browser =KeyboardEvent.key= spelling,
  which the SDL side translates to match), pointer, wheel, resize, close —
  the orrery's =Event= was four application-specific constructors, flagged
  in its notes as the weak point.
- *Two shader entry points.* Lines carry only a position, so =vs_line=
  consumes them directly; no fake normal attribute, and the line pipeline's
  vertex layout is generated from its own field list.

* The linear frame token

=beginFrame= mints a linear token; every draw consumes and re-issues it;
=endFrame= consumes it finally. Drawing after the end, dropping a begun
frame, or drawing twice from one token are type errors, checked by
=make check= against the exact expected diagnostic (=Tests/=). The rule the
orrery measured, kept here: *linear tokens sit at resource boundaries and
are never threaded through a per-item loop.* =runK='s recursion is not a
self tail call, so each bind costs a stack frame on the JS backend and
overflows between 8 000 and 10 000 binds — hence =drawMany=, which loops
inside one lifted =IO= action. The swarm example runs 10 000 bodies in the
browser as the regression test for exactly that.

* One description of the GPU contract

=Offler.Gfx.Layout= holds the uniform blocks, their fields, and both vertex
layouts. Everything else is derived:

- the WGSL =struct Globals= / =struct Obj= / =struct VertexIn= /
  =struct LineIn= and their =@group/@binding= declarations, prepended to the
  authored shader;
- the GLSL =layout(location=n) in= declarations, spliced after =#version=;
- the bind-group-layout and vertex-attribute *spec strings* that both
  WebGPU-flavoured backends decode once at startup — Idris cannot build a
  nested descriptor across either FFI, so the description crosses as
  =0,3,0,176;1,3,1,112= and five lines of JS or fifteen of C decode it;
- every byte offset and stride the pokes use, as *literals proved equal to
  the computed layout* at multiplicity 0:

#+begin_src idris
  globalSize : Int
  globalSize = 176

  0 globalSizeOk : Layout.globalSize = Layout.structSize Layout.globalFields
  globalSizeOk = Refl
#+end_src

Grow the object uniform past its slot, misalign a field, or declare a vertex
attribute wider than one location, and the module stops compiling. The
guarantees follow the orrery's cost ladder: erased indices and private
constructors (free) catch most of the real bugs; the one checked-at-runtime
step is =slot=, a single comparison covering both the scratch bound and the
dynamic offset, because =objFloats * 4 = objStride= is proved.

What is deliberately /not/ guaranteed: two arrays of equal capacity remain
interchangeable, and a computed index is tested rather than proved — =Int=
is primitive, so its order theory would have to be postulated (the
=Data.Int.Order= pattern), and multiplication monotonicity is missing there.
Bounds arithmetic is written not to overflow (=i <= n - w=, never
=i + w <= n=), which matters because =Int= is 32-bit on the JS backend.

** The run-time bounds tests, and turning them off

The erased indices, the proofs, the private constructors and the linear
token cost nothing at run time — erasure is free, so there is nothing to
toggle there. The only checks that run are:

- =window= / =slot=, the checked constructors, which §8.1 of the orrery's
  notes priced at +43 ns per object on Chez and +20 ns on Node — and
  attributed to the =Maybe= they allocate, not to the comparison. offler
  keeps them on the /cold/ paths only: single =draw= calls, line overlays,
  mesh uploads.
- The per-object hot path — =drawMany='s batch fill — goes through
  =pokeObjects= instead, whose bound is a bare comparison inside the module
  that owns the invariant: the same test, exactly once in the library, with
  its result moved from a heap value to a branch. That recovers the
  measured §8.1 cost without weakening anything a caller can reach; =slot=
  remains the only way in from outside, and =make check= still proves it
  (=Tests/ForgedSlot.idr=).

On top of that sits the switch:

#+begin_src sh
  make BOUNDS=trusted      # batch bounds tests off
  make                     # BOUNDS=checked is the default
#+end_src

The flag becomes the generated =Offler.Gfx.Config= module — the same
mechanism as the embedded shaders, regenerated only when the value changes —
whose =boundsMode : Bounds= is a compile-time constant. =pokeObjects=
branches on it /once, outside the loop/, and because the constant reduces,
the untaken loop is dead code: a =trusted= bundle contains no =goChecked=
at all, verifiable by grep. An earlier design indexed the API by a
type-level flag with the result type computed from it
(=Checked ↦ Maybe (At cap w)=, =Trusted ↦ At cap w=); it works, but every
call site must then handle both result types, and the toggle becomes the
complexity. A value-level constant that constant-folds gets the same
machine code without bifurcating the API.

=Trusted= is only sane when the application bounds its own draw count:
past the cap, the JS backend silently drops the writes and the C side
corrupts the heap. The default is =checked=, and since the checked test is
a bare comparison the notes measured as free, there is little reason to
ship =trusted= — it exists to make the cost of the guarantee inspectable
rather than argued about.

* Performance rules inherited as architecture

From the measurements in the orrery's notes, taken as constraints rather
than advice:

- Hot numeric data lives in flat foreign =Float32Array= / =float*= buffers,
  not Idris records; Chez heap-allocates every intermediate flonum and is
  roughly 5× slower than V8 on record-heavy per-frame work.
- Foreign calls are batched around the natural unit of the data: =poke16=
  writes a whole matrix, line vertices are padded to four floats so one call
  writes two of them, and per-object uniforms are filled CPU-side and
  uploaded in *one* =writeBuffer= per frame — per-object queue writes are
  what once made WebGPU a third of WebGL2's speed.
- Nothing per-frame builds lists with non-tail recursion. The Prelude's
  ranges overflow V8 near 5 700 elements (=takeUntil= has no accumulator
  transform), so =Offler.Math.range= is total, tail-recursive, and
  ascending-or-empty.
- Batched draws loop on the far side of the FFI where possible:
  =drawMany= records its slices in one foreign call on both WebGPU-flavoured
  backends.

* The native build

Same scene code, compiled with =--cg chez=. SDL3 rather than GLFW because
wgpu wants a =CAMetalLayer= on macOS and =SDL_Metal_CreateView= produces one
without Objective-C. Surface creation is the only per-platform function,
selected on =SDL_GetCurrentVideoDriver()= at run time (X11 and Wayland in
one binary). The C shim holds no scene logic and no layout constants — the
specs arrive from =Offler.Gfx.Layout= at init. The Makefile drops
=liboffler.so= into each =build/exec/<example>_app/=, where the generated
launcher's =LD_LIBRARY_PATH= already points, so binaries run with no
environment set.

Headless verification:

#+begin_src sh
  nix develop --command scripts/headless-shot.sh shapes /tmp/shapes.png 8
#+end_src

runs an example under Xvfb with lavapipe as the Vulkan device and grabs the
window. The script encodes the two traps: SDL3 prefers Wayland whenever
=WAYLAND_DISPLAY= is set regardless of =DISPLAY=, and wgpu dlopens
=libvulkan.so.1=, which the dev shell puts on the library path.

* Known limits, in the order they would matter

- No textures, and no way to feed a custom shader through the typed layout
  yet — the standard pipeline pair is the only one. The layout module is
  written to describe more than it currently instantiates.
- One directional light plus ambient. Point lights want a light array in the
  globals, which is a =Layout= change plus a shader loop.
- Every object is still a draw call (at most one bind); instancing from
  storage buffers is the known next step for the swarm's ceiling, exactly as
  the orrery's notes conclude.
- The per-frame object cap is =maxObjects = 10240= slots of 256 bytes.
- Meshes are never freed; the intended pattern is create-at-startup.
- Alpha on mesh materials writes but does not blend (the mesh pipeline is
  opaque, as bevy's default); only the line pipeline blends.
- =Escape= closing the native window is platform policy, not scene code.

* Testing

- =make check= — six programs that must fail to compile, each asserting
  /why/ it was rejected (a linearity error, a private constructor, a =So=
  bound, a stride mismatch). A negative test that does not say why is not a
  test: the orrery's first version passed vacuously on misnamed modules.
- =Checks/StackCheck.idr=, run by =make check= — the other kind of
  guarantee: a program that must /run/, filling all 10 240 slots on the
  node backend, where the stack is scarcest, plus a grep of the generated
  output for the =__tailRec= trampoline the loop depends on. It exists
  because the first version of =pokeObjects= compiled to a curried
  recursion the trampoline could not see and overflowed V8 at exactly the
  cap — invisible in the source, invisible to every compile-time check,
  caught only by running the loop at scale and reading the output. (The
  fix: the loop is written in =PrimIO= with the world bound on the
  left-hand side, so the recursive call is saturated and trampolines.)
- =scripts/headless-shot.sh= — pixels from the native build without a GPU or
  a display.
- The browser pages surface uncaught errors and unhandled rejections into a
  visible error box, because most of the startup path is asynchronous and
  would otherwise fail to a silent blank canvas.
